### 4.2 任务调度架构

#### 4.2.1 每日跑批流程

```
APScheduler (cron: 0 0 * * *)
   │
   ▼
[daily_batch job]
   │
   ├─ 1. fetch_orders()      # 拉取/读取订单与特征（CSV 已入库则跳过）
   ├─ 2. calc_risk()         # 对未计算订单算风险概率 → 写 risk_prob
   ├─ 3. map_risk_tier()     # 按 active risk_config 映射风险档
   ├─ 4. generate_tasks()    # 核心调度逻辑（见下）
   └─ 5. assign_tasks()      # 分配给催收员
```

#### 4.2.2 任务生成核心逻辑

```python
def generate_tasks(today: date, batch_id: str):
    config = get_active_risk_config()
    # 查所有未支付订单
    unpaid_orders = get_unpaid_orders()
    
    for order in unpaid_orders:
        tier = order.risk_tier
        schedules = get_schedules(config.id, tier)  # 该档所有催收时点
        
        for sch in schedules:
            due_date = order.win_bid_date + timedelta(days=sch.day_offset)
            
            # 命中条件：应催日 <= 今日 且 该时点未生成过任务（幂等）
            if due_date <= today:
                # 幂等检查：同 order + 同 day_offset 不重复
                if not task_exists(order.id, sch.day_offset, batch_id):
                    # 二次确认：当前仍未支付才生成
                    if order.pay_status != 'PAID':
                        create_task(order, sch, due_date, batch_id)
```

> **幂等设计**：`batch_id`（日期）+ `order_id` + `day_offset` 三元组唯一约束，防止重复生成。

#### 4.2.3 任务分配算法

```python
def assign_tasks(today_tasks: list[Task]):
    # 按风险档排序：HIGH > MEDIUM > LOW；同档按账龄倒序
    sorted_tasks = sort_by_priority(today_tasks)
    
    collectors = get_active_collectors()  # 3 名
    # 负载均衡：轮询分配，但保证高风险优先给当前负载最低的人
    loads = {c.id: get_pending_count(c.id) for c in collectors}
    
    for task in sorted_tasks:
        assignee = min(loads, key=loads.get)  # 当前负载最低者
        task.assignee_id = assignee
        task.status = 'PENDING'
        loads[assignee] += 1
```

### 4.3 话术系统架构

#### 4.3.1 双层架构：固定模板 + AI 提示词模板

```
催收员请求话术(task_id)
        │
        ▼
[话术编排器 recommend_talks / generate_talk]
        │
   ┌────┴────┐
   ▼         ▼
[固定模板匹配]  [AI 提示词匹配]   ← AI 可开关
 (FIXED)      (AI_PROMPT)
   │         │
   ▼         ▼
 build_values 渲染  build_prompt → LLM 生成
 ({供应商名称}等44个)  (合规基线 + 后台 system)
   │         │
   └────┬────┘
        ▼
推荐话术（固定模板直接展示 / AI 生成 markdown 渲染）
```

- 固定模板（FIXED）：匹配后渲染占位符直接展示，未配显示「该轮次未配话术」
- AI 提示词模板（AI_PROMPT）：匹配后渲染 system/user prompt 喂 LLM 生成（无匹配降级内置默认 prompt）
- AI 合规基线：后台配的 system prompt 追加在内置合规基线之后，不可覆盖；is_compliant 输出校验永远启用

#### 4.3.2 模板匹配逻辑（二维 [风险档 × 轮次]）

```python
def match_templates(db, task, *, template_type="FIXED") -> list[TalkTemplate]:
    # 二维精确匹配，无 ANY 兜底
    return db.query(TalkTemplate).filter(
        TalkTemplate.is_active.is_(True),
        TalkTemplate.template_type == template_type,
        TalkTemplate.risk_tier == task.risk_tier,
        TalkTemplate.scene == task.scene,  # ROUND_N
    ).order_by(TalkTemplate.id.asc()).all()
```

> 账龄段、用户特征不再参与匹配，降为话术正文的可插入变量（build_values 取值）。

#### 4.3.3 AI 话术生成（LLM Provider 抽象 + 模板化）

```python
# talk_engine/llm_provider.py
class LLMProvider(ABC):
    @abstractmethod
    def generate(self, system_prompt: str, user_prompt: str) -> str: ...

class OpenAICompatibleProvider(LLMProvider): ...  # 接 OpenAI 兼容接口（glm/DeepSeek/通义）
class MockLLMProvider(LLMProvider): ...            # MVP 离线 mock

# 生成 Prompt 组装（读 AI_PROMPT 模板，无则降级内置默认）
def build_prompt(db, task, order, feature, *, today) -> tuple[str, str]:
    ai_templates = match_templates(db, task, template_type="AI_PROMPT")
    if not ai_templates:
        return _default_prompts(task, order, feature)  # 降级内置默认 prompt
    tmpl = ai_templates[0]
    admin_system = render(tmpl.system_prompt, ...)  # 后台 system（渲染占位符）
    # 合规基线 + 后台 system（追加非覆盖，D7）
    system = f"{_COMPLIANCE_BASELINE}\n{admin_system}" if admin_system.strip() else _COMPLIANCE_BASELINE
    user_prompt = render(tmpl.user_prompt, ...)
    return system, user_prompt
```

> **开关控制**：`ai_config.enabled`，关闭时仅返回固定模板话术。
> **合规基线** `_COMPLIANCE_BASELINE` 模块级常量，后台 system prompt 追加其后不可覆盖；`is_compliant` 输出校验永远启用（D7）。
> **降级**：LLM 失败/合规校验不通过/无 AI_PROMPT 模板，均降级固定模板（设计约束 #2）。

#### 4.3.4 占位符注册表（44 个，覆盖 Order+OrderFeature 全部业务字段）

```python
# talk_engine/placeholders.py
@dataclass(frozen=True)
class PlaceholderInfo:
    key: str          # 花括号内标识符，如 "供应商名称"
    description: str  # 中文说明
    group: str        # 分组：基础/标的/催收/供应商归属/缴费历史/活跃度/资质标签

# 44 个占位符分 7 组（基础5/标的7/催收7/供应商归属5/缴费历史3/活跃度8/资质标签9）
# validate_placeholders(text) -> list[str]  校验未知占位符（保存模板时 400 拒绝）
# available_placeholders() -> list[PlaceholderInfo]  供前端「插入变量」展示
```

## 7. AI 功能架构（基于 agent-app-builder 方法论）

本系统含两类 AI 能力，遵循"抽象 Provider + 可替换 + 可降级"原则：

### 7.1 AI 能力清单

| 能力 | 类型 | MVP 实现 | 后续演进 |
|------|------|---------|---------|
| 风险概率预测 | 预测模型 | Mock Provider（规则加权） | Algorithm Provider（训练好的分类模型） |
| 智能话术生成 | LLM 生成 | Mock 或真实 LLM（可开关） | 真实 Claude/OpenAI，基于反馈优化 |

### 7.2 控制分配（Control Allocation）考虑

| 决策点 | 控制方 | 说明 |
|--------|--------|------|
| 是否调用 AI 生成话术 | 系统+人 | 系统按维度推荐模板；催收员可主动触发 AI 生成/润色 |
| AI 生成内容是否采用 | 人 | 催收员决定采用哪段话术，并标记反馈 |
| 风险档阈值调整 | 人（主管） | 管理员配置，系统不自动改阈值 |
| 任务分配 | 系统 | 系统按规则分配，主管可手动改派 |

### 7.3 失败与降级

| 场景 | 降级策略 |
|------|---------|
| LLM 调用超时/失败 | 返回模板话术，记录失败，不影响催收 |
| 风险算法服务不可用 | 使用上次缓存风险概率，标记 stale |
| 跑批失败 | 重试 3 次，失败告警，不影响历史任务 |

### 7.4 工具设计（Tool Design）

- 话术生成的 LLM 仅做"文本生成"单一职责，不赋予调用业务系统/改数据的工具（避免误操作）。
- 风险算法仅做"概率计算"，不直接生成任务（任务生成由确定性 task_engine 负责）。
