## 1. 背景与目标

### 1.1 业务背景

供应商在中标后需缴纳"平台使用费"。部分供应商存在拖延缴费甚至欠费的情况，当前催收依赖人工经验，存在以下问题：

- **介入不及时**：缺乏基于风险的差异化节奏，对所有欠费一视同仁，高风险用户错过最佳干预窗口。
- **资源分配粗放**：3 名专职催收员手工分单，无法保证高风险优先、负载均衡。
- **话术不统一**：催收话术依赖个人经验，缺乏规范，异议处理能力参差。
- **缺少数据视角**：欠费率、回款率、任务完成率等无统一可视化，难以度量催收效果。

### 1.2 产品目标

构建一套 AI 辅助催收系统，在供应商中标时刻基于其特征预测欠费风险概率，按风险档自动生成催收任务并分配给催收员，同时提供规范话术与 AI 增强话术，最终通过数据大盘监控整体态势。

**核心目标**：高风险用户被及时干预，其他风险用户按规范被执行催收，整体回款率提升、人工成本降低。

### 1.3 系统边界

| 在本系统范围内                     | 不在本系统范围内                      |
| ---------------------------------- | ------------------------------------- |
| 风险概率计算（现 mock，后接算法）  | 算法模型训练与离线特征工程平台        |
| 催收任务生成与分配                 | 平台层面的业务阻断（限制投标/中标等） |
| 催收工作台与结果回填               | 真实交易平台的订单管理                |
| 话术推荐与 AI 生成                 | 实际资金收付与对账                    |
| 数据大盘                           | 逾期转法务的线下流程                  |
| 与真实平台的订单/特征数据 API 对接 | 业务平台侧的改造                      |

> 说明：用户明确"平台层面的阻断不是在这个系统上做的"。本系统的"阻断"语义=催收节点强提醒+人工即时介入，而非交易阻断。

## 2. 名词定义

| 术语       | 定义                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------- |
| 平台使用费 | 供应商中标后应向平台缴纳的服务费                                                            |
| 中标时刻   | 中标结果通知日（calibration_result_notice_date），作为风险计算与账龄起算基准                |
| 风险概率   | 模型/mock 输出的 0~100% 值，表示该笔订单在未来 30 天内**欠费**的概率。值越高=风险越高 |
| 风险档     | 按风险概率阈值划分的高/中/低三档，决定催收节奏                                              |
| 催收时点   | 风险档配置中规定的"中标后第 N 天"应催收的日期                                               |
| 催收任务   | 到达催收时点且届时仍未支付时，系统生成的具体催收工单                                        |
| 账龄       | 自中标日起经过的天数（MVP 采用中标后天数，简单直观）                                        |
| 催收场景   | 首催 / 二催 / 三催 / 异议处理 / 承诺跟进                                                    |
| 应缴日     | 中标后第 30 天（业务约定缴费窗口）                                                          |

## 3. 用户角色

| 角色                              | 描述                       | 核心诉求                                                                         |
| --------------------------------- | -------------------------- | -------------------------------------------------------------------------------- |
| **催收员**（3 名专职）      | 执行催收任务的一线人员     | 每日清晰看到分配给自己的任务，按优先级处理；催收时获得话术辅助；快速回填处理结果 |
| **催收主管**                | 管理催收团队、监控整体态势 | 配置风险档阈值与催收节奏；查看大盘；分配/调整任务；评估团队绩效                  |
| **系统管理员**              | 负责系统配置与数据接入     | 配置数据源/API、风险档规则、话术模板；管理用户权限                               |
| **数据/算法工程师**（后续） | 维护预测算法               | 替换 mock 概率为真实算法（MVP 后介入）                                           |

## 4. 核心业务流程

### 4.1 端到端流程

```
① 数据接入        ② 风险计算        ③ 任务生成        ④ 任务分配        ⑤ 催收执行        ⑥ 结果回填        ⑦ 大盘监控
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 真实平台API│    │ 风险概率  │    │ 催收时点  │    │ 3名催收员 │    │ 催收工作台│    │ 处理结果  │    │ 日/周/月  │
│ 或CSV上传 │───▶│ 0~100%   │───▶│ 到达+未付 │───▶│  高风险优先│───▶│ 话术推荐  │───▶│ 已缴/承诺/│───▶│ 数据大盘  │
│ (每日凌晨)│    │ (现mock)  │    │ =生成任务 │    │ 负载均衡  │    │ AI生成    │    │ 异议/失联 │    │          │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

### 4.2 每日跑批流程（凌晨 00:00 触发）

1. **拉取订单与特征**：通过 API 从真实业务平台获取平台使用费订单及对应特征（MVP 阶段：读取上传的 CSV）。
2. **计算风险概率**：对每笔未支付订单调用风险计算模块（MVP：mock；后续：预测算法服务）。
3. **风险档映射**：按配置阈值将概率映射为高/中/低档。
4. **生成催收任务**：扫描所有未支付订单，判断"中标日 + 催收时点"是否命中今日，且当前仍未支付 → 生成催收任务。
5. **任务分配**：按"高风险优先 + 负载均衡"原则，将当日任务分配给 3 名催收员。
6. **通知**：向催收员推送当日待办（站内 + 可选外部通知）。

### 4.3 单笔催收执行流程（催收员视角）

```
打开催收工作台 → 查看今日待办(按风险/账龄排序) → 领取/进入任务
   → 查看订单详情 + 用户特征画像
   → 系统按 [风险档×账龄×场景×用户特征] 推荐基础话术
   → [可选] 一键 AI 生成/润色话术
   → 执行催收(电话/短信/站内信)
   → 回填处理结果(已缴费/承诺还款/异议/失联/其他) + 备注
   → 任务流转(完成/改期/升级)
```

## 5. 功能需求

### 5.1 数据接入模块（MVP）

| 编号      | 需求                                                         | 优先级 |
| --------- | ------------------------------------------------------------ | ------ |
| F-DATA-01 | 支持 CSV 上传，解析 37 列特征结构（GBK/UTF-8 自动识别）      | P0     |
| F-DATA-02 | 上传后数据入库，建立订单与特征关联                           | P0     |
| F-DATA-03 | 提供"重新计算风险"按钮，对入库订单批量生成 mock 风险概率     | P0     |
| F-DATA-04 | 预留真实平台 API 对接接口（订单拉取 + 特征拉取），MVP 不实现 | P1     |
| F-DATA-05 | 数据预览：查看上传的订单列表与特征值                         | P1     |
| F-DATA-06 | 编码/格式校验，上传失败时给出明确错误提示                    | P0     |

**特征字段清单**（沿用示例 CSV 的 37 列结构）：

- **标签（5 列）**：中标日期、实际支付时长_天、标签_30/90/180/365天是否欠费
- **标识（7 列）**：供应商编号、供应商名称、招标编号、服务费订单号、招标类型、采购类型、注册地区
- **A 类 缴费历史（3 列）**：历史平台使用费订单数、上次缴费历时_天、历史缴费平均历时_天
- **B 类 活跃度与支付（8 列）**：服务市场历史支付金额、历史报名/投标/中标次数、历史中标率、近90天投标活跃度、首次中标距本次间隔_天、中标时是否会员、中标前购买会员次数
- **C 类 资质与标签表（9 列）**：注册资金、注册时间距中标间隔_天、平台入驻时间距中标间隔_天、最早入库时间距中标间隔_天、供应商品类、标签表历史中标率、股份优质评级次数、合作单位数量、累计履约项目数
- **D 类 时间周期（4 列）**：中标月份、是否月末、是否季末（中标月份为派生字段）

### 5.2 风险档配置模块（MVP）

| 编号      | 需求                                                                          | 优先级 |
| --------- | ----------------------------------------------------------------------------- | ------ |
| F-RISK-01 | 风险概率阈值配置：高风险下限 X%、中风险下限 Y%（< Y% 为低），X、Y 可调        | P0     |
| F-RISK-02 | 每档催收时点配置：支持配置多个催收节点（中标后第 N 天），每个节点对应催收场景 | P0     |
| F-RISK-03 | 配置生效后，对历史入库订单可触发重算风险档                                    | P0     |
| F-RISK-04 | 配置版本管理：保存历史配置，支持回滚                                          | P1     |
| F-RISK-05 | 默认配置预设：高风险=7/15/30天，中风险=30天，低风险=90天                      | P0     |

**默认风险档配置示例**：

| 风险档 | 概率阈值 | 催收时点（中标后第 N 天） | 对应场景           |
| ------ | -------- | ------------------------- | ------------------ |
| 高风险 | ≥ 70%   | 第 7 / 15 / 30 天         | 首催 / 二催 / 三催 |
| 中风险 | 30%~70%  | 第 30 天                  | 首催               |
| 低风险 | < 30%    | 第 90 天                  | 首催               |

> 上述阈值与时点均为默认值，管理员可在后台调整。

### 5.3 催收任务调度模块（MVP）

| 编号      | 需求                                                                     | 优先级 |
| --------- | ------------------------------------------------------------------------ | ------ |
| F-TASK-01 | 每日凌晨跑批：扫描未支付订单，命中催收时点且未支付 → 生成催收任务       | P0     |
| F-TASK-02 | 任务状态机：待分配 → 待处理 → 处理中 → 已完成（终态）；支持改期、升级 | P0     |
| F-TASK-03 | 任务分配：高风险优先分配，3 名催收员负载均衡                             | P0     |
| F-TASK-04 | 手动调整：主管可重新分配、改派任务                                       | P1     |
| F-TASK-05 | 同一订单同一催收时点不重复生成任务（幂等）                               | P0     |
| F-TASK-06 | 任务去重：若订单在某时点已催收且未关闭，不重复生成                       | P0     |
| F-TASK-07 | 支持手动触发跑批（测试用）                                               | P0     |

**任务状态机**：

```
待分配 ──分配──▶ 待处理 ──领取──▶ 处理中 ──回填结果──▶ 已完成(终态)
                                              │
                                              ├── 承诺还款 → 改期(承诺日再催) → 待处理
                                              ├── 异议 → 升级/转异议处理 → 待处理
                                              └── 失联 → 标记+改期
```

## 6. 非功能性需求

| 类别   | 要求                                                    |
| ------ | ------------------------------------------------------- |
| 性能   | 跑批处理 10000 笔订单 ≤ 5 分钟；工作台列表加载 ≤ 2 秒 |
| 可用性 | 系统可用性 ≥ 99.5%（工作日 8:00-20:00）                |

| 可扩展 | 风险算法、LLM 提供商、数据源均通过接口抽象，可替换      |

## 8. 验收标准（MVP）

1. 可上传 CSV 并解析入库，数据完整无丢失。
2. 管理员可配置风险档阈值与催收时点，配置后生效。
3. 跑批可生成催收任务，高风险订单按时点生成多轮任务，未支付才生成。
4. 3 名催收员可登录工作台，看到分配给自己的任务并处理。
5. 单笔催收可看到推荐话术，可触发 AI 生成（mock 或真实 LLM）。
6. 处理结果可回填，任务状态正确流转。
7. 大盘可展示当日核心指标。
